# 远程桌面归属 adapter，锁屏能力分期

在“桌面 App 管理受控组件”“仅扩展 adapter”“独立受控程序”三个边界选项中，用户选择仅扩展本仓库 adapter，不修改桌面 App 所在仓库或 agent 核心逻辑。此边界保留现有桌面端产物消费契约，但把 macOS 捕获、输入与系统授权的集成/打包验证责任放到 adapter；若无法保持契约，必须报告并重新决策，而不是隐式引入另一仓库改动。

用户希望后续可连接已登录且锁屏的 Mac 并手动输入密码解锁，但在“锁屏阻塞首版”和“锁屏延后”之间明确选择先做解锁桌面。因此锁屏解锁留作后续需求，不能把它宣称为首版能力。上述边界已由用户确认，保持不变。当前实现保持单 adapter 可执行文件边界；真实 iPhone、最终冻结产物、TCC 与 TURN/性能验证仍待完成，证据及未验证事项见 [需求文档](../requirements/goal.md) 和 [实现说明](../remote-desktop.md)。
