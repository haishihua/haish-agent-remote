## Repair and regression tests

- `server/desktop.py`: one session-owned close task shielded from caller cancellation. Stop marks closed/releases input before awaiting; concurrent disable/watchdog/connection/HTTP cleanup joins the same task. Slot stays occupied during cleanup to prevent overlap; cleared after cleanup.
- Before repair, deterministic cancellation-sensitive fake peer reproduced: cancel first stop while peer.close is pending, then second stop times out with busy=true and peer cancellation=true. aiortc 1.14 close stores a Future before awaits and does not finalize it if cancelled; this corroborates a concrete cancellation failure mode, not proof of the exact physical timeout cause.
- `setRemoteDescription` previously lay outside the 12s timeout and can await mDNS resolution. Entire remote-description/answer/gather negotiation now has a 12s budget, not just setLocalDescription.
- `tests/test_desktop.py`: cancelled stop cannot cancel peer cleanup; disable joins watchdog cleanup once; blocked remote-description times out with 503 and frees slot. Existing revoke test now awaits cleanup completion instead of assuming one event-loop turn.
